## 快速上手

```bash
cp deploy/start.sh /root/start.sh && chmod +x /root/start.sh

bash /root/start.sh          # 交互菜单
bash /root/start.sh 4        # 启动无人值守守护（会自动 disable mrs.timer）
bash /root/start.sh 10       # 查看当日执行计划
bash /root/start.sh 8        # 立即补跑一轮（不占计划点）
bash /root/start.sh log      # 跟随日志
bash /root/start.sh 5        # 停止守护并卸载保活
```

菜单：

| 选项 | 作用 |
|---|---|
| `1` | 前台跑一轮 |
| `2` | 清理缓存 |
| `3` / `3r` | 备份 / 恢复凭证 |
| **`4`** | **启动无人值守守护**（+ 装断电保活 crontab） |
| `5` | 停止守护（+ 卸载保活） |
| `6` | 推送设备公网 IPv6 到微信 |
| `7` | 手动推送当日汇总 |
| **`8`** | **立即跑一轮**（含自愈 + 推送，不等计划点） |
| `9` / `log` | 跟随今日日志 |
| **`10`** / `plan` | **查看当日执行计划** |

## 配置项

全部可通过环境变量覆盖（写进 `/opt/mrs/.env` 或启动时前缀指定）：

| 变量 | 默认 | 含义 |
|---|---|---|
| `SCHED_SLOTS` | `02:00,10:00,17:00` | 候选锚点（`HH:MM`，逗号分隔） |
| `SCHED_PICK` | `2` | 数字 = 固定抽 N 个；`variable` = 在 `[1, SCHED_PICK_MAX]` 内随机 |
| `SCHED_PICK_MAX` | `2` | `variable` 模式的随机上限 |
| `SCHED_DELAY_MAX` | `60` | 每个锚点的**额外**随机延迟，`[0, N]` 分钟 |
| `SCHED_MIN_GAP` | `30` | 两个执行点之间的最小间隔（分钟） |
| `SCHED_SEED_SALT` | `mrs-rk3229` | 伪随机种子盐值（**改动会重新洗牌当日计划**） |
| `SCHED_FALLBACK` | `false` | `true` = 退回「每天固定单点」模式（逃生阀） |
| `UNATTEND_HOUR` | `1` | 仅回退模式使用（固定单点的整点） |

`SCHED_DIR` 默认 `$BASE/.unattended`，存放 `schedule.plan` 与 `day.stats`。

### 示例

```bash
# 每天三个锚点里随机抽 1~2 个，延迟 0~90 分钟，最小间隔 45 分钟
SCHED_SLOTS=01:30,09:45,16:20 SCHED_PICK=variable SCHED_PICK_MAX=2 \
SCHED_DELAY_MAX=90 SCHED_MIN_GAP=45 bash /root/start.sh 4
```

## 调度流程

```
守护启动
   │
   ├─ sched_validate          校验并规范化配置（非法值兜底）
   ├─ plan_load               载入/生成当日计划（按日期校验）
   │     └─ sched_compute_plan  用 sha256(盐|日期|序号) 抽选 + 加延迟 + 排序 + 拉平间隔
   │
   └─ 循环 ──────────────────────────────────────────────┐
         │                                               │
         ├─ plan_load        取当日计划                  │
         ├─ 找最早 pending                                │
         │    ├─ 没有 pending → sleep 到次日 00:00 ───────┤
         │    ├─ 已过点且超宽限(±600s) → 标 missed ───────┤
         │    └─ 未到点 → 打印「下次自动执行」→ sleep ────┤
         │                                               │
         └─ 到点 → ① 原子认领(先标 done)                  │
                   ② is_mrs_running? 是 → 跳过本轮       │
                   ③ 预算检查 DAY_BUDGET_SECONDS         │
                   ④ monitor_round() 执行一轮 ───────────┘
```

## 四个核心设计

### 1. 确定性伪随机

**问题**：如果用 `$RANDOM`，每次调用结果不同 —— 守护重启、cron 自检、用户查看计划
都会算出**不同的当日计划**，导致「同一天内计划一致」「不重复触发」都无法保证。

**解决**：用哈希做确定性伪随机。

```bash
sched_rand() {   # 确定性伪随机 [0, mod)
    _seed="$1"; _idx="$2"; _mod="$3"
    [ "$_mod" -gt 0 ] 2>/dev/null || { printf '0\n'; return 0; }
    _hex=$(printf '%s' "$SCHED_SEED_SALT|${_seed}|${_idx}" | sha256sum 2>/dev/null | cut -c1-8)
    [ -n "$_hex" ] || { printf '0\n'; return 0; }
    printf '%s\n' $(( 16#$_hex % _mod ))
}
```

- **同一天内**：任意时刻、任意进程、任意重启后算出的计划**完全一致**；
- **跨天**：日期变了，哈希输入变了，计划自动换；
- **可复现**：给定 `SCHED_SEED_SALT` + 日期，计划可精确重算。

**抽选算法**（等价于「无放回随机抽 N 个，且与顺序无关」）：

1. 对每个锚点算排序键 `sched_rand(date, 1000+i)`，左侧 `%07d` 补零保证 `sort` 按数值正确排序；
2. 升序取前 N 个；
3. 每个锚点叠加 `sched_rand(date, i)` 得到的 `[0, SCHED_DELAY_MAX]` 延迟；
4. 按最终时刻排序；
5. 做最小间隔拉平。

### 2. 计划落盘与日期校验

计划写在 **`$BASE/.unattended/schedule.plan`**，**不放 `/tmp`** —— 目的是**断电重启后仍能恢复**。

```
<日期> <序号> <epoch> <锚点> <延迟> <状态>
20260925 0 1790304300 10:00 45 done
20260925 1 1790327940 17:00 19 pending
```

状态：`pending` | `done` | `missed`。

- `plan_load` 是幂等的：**日期一致且有行就直接复用**（保留 `done` / `missed`，不重抽）；
- 日期不匹配 → 自动重算并重置 → **天然支持跨天**。

**分钟刻度 vs epoch 的分离**：`sched_compute_plan` 输出「从当天 0 点起的分钟刻度」
（允许 ≥ 1440 表示跨午夜），`sched_tick_to_epoch` 用 `date -d "<日期> 00:00:00" +%s` 加分钟数换算成 epoch。

这样做的原因有两个：① 保证 DST / 时区换算正确；② **不会把次日 00:25 回绕成当天早上**。

### 3. 原子认领防重复触发

**先标记 `done` 再执行**：

```bash
plan_set_status "$_slot_idx" "done"     # ① 先认领
log_msg "===== 到达计划执行点 #$((_slot_idx + 1)) ====="
# ② 再执行本轮
```

即使进程在①之后、执行途中被 `kill -9`，重新拉起的守护也**不会重复跑同一个点**。
反过来（先执行后标记）就会出现「被 kill 后被重复触发」。

### 4. 手动运行与自动调度隔离

**设计原则：守护单例锁 ≠ 单轮执行锁，两者必须分开。**

原来的实现里，选项 8（立即跑一轮）与守护共用同一个锁，导致**守护在跑时无法手动补跑**
（报「已有守护在运行」），而且选项 8 还会误「认领」掉一个当日计划点。

v5 的拆分：

| 入口 | 函数 | 取守护锁 | 读写计划文件 |
|---|---|---|---|
| 选项 4 守护 / 计划点触发 | `do_unattended` → `monitor_round()` | ✅ | ✅ |
| 选项 8 立即跑一轮 | `do_run_now()` → `monitor_round()` | ❌ | ❌ |

- 单轮执行体抽成 `monitor_round()`，被守护循环与选项 8 **共用**，保证行为一致；
- 选项 8 只用 `is_mrs_running` 判断**真冲突**（是否真有一轮 MRS 在跑）。

## 边界处理

| 场景 | 处理 |
|---|---|
| **跨天** | 计划文件按日期校验，日期不匹配自动重算 |
| **跨午夜** | 分钟刻度 ≥ 1440 落到次日（`23:30 + 55分` = 次日 `00:25`，已验证） |
| **进程重启 / 断电重启** | 计划落盘且保留 `done`/`missed`，已完成点不会重跑 |
| **已过点但仍在小窗口内** | ±600 秒宽限内照常执行（记录实际偏差） |
| **已过点且超出宽限** | 标记 `missed`，不再补跑 |
| **两执行点太近** | 后者右移，最多 8 轮；推不动则丢弃（输出 `DROP <src>`） |
| **非法配置** | `99:99,abc` 被忽略、`pick=xx` → 1、`delay=yy` → 60、`gap=zz` → 30 |
| **抽数超过锚点数** | 自动收敛（如 `SCHED_PICK=8` 但只有 2 个锚点 → 取 2） |
| **上一轮还在跑** | `is_mrs_running` 拦截，跳过本次，不并发启动 |
| **当日预算用尽** | `DAY_BUDGET_SECONDS`（默认 10 小时）到顶后跳过并推送提示 |

## 日志字段

每次到点执行都会记录**计划时刻 / 实际触发时刻 / 偏差**：

```
2026-09-25 10:50:08 [计划] 当日执行计划(日期=2026-09-25 | 候选=02:00,10:00,17:00 | 抽取=2(固定) | 延迟=0~60分钟 | 最小间隔=30分钟)
2026-09-25 10:50:08        #1 锚点10:00 + 延迟45分钟 → 2026-09-25 10:45:00 [pending]
2026-09-25 10:50:08        #2 锚点17:00 + 延迟19分钟 → 2026-09-25 17:19:00 [pending]
2026-09-25 10:50:08 下次自动执行: 2026-09-25 10:45:00 (锚点10:00 + 延迟45分钟, 23031秒后)
2026-09-25 10:50:08 ===== 到达计划执行点 #1 =====
2026-09-25 10:50:08 [计划] 计划时刻=2026-09-25 10:45:00 | 锚点=10:00 | 随机延迟=45分钟
2026-09-25 10:50:08 [计划] 实际触发时刻=2026-09-25 10:50:08 | 与计划偏差=308秒
```

| 字段 | 含义 |
|---|---|
| `当日执行计划` | 当天抽中的锚点、抽取数量、延迟范围、最小间隔 |
| `锚点=X + 延迟=Y分钟` | 该点由哪个锚点叠加多少延迟得到 |
| `计划时刻` | 计划应该跑的时刻（epoch 换算后） |
| `实际触发时刻` | 守护真正开始执行的时刻 |
| `与计划偏差` | 实际 − 计划（秒）。正常在 ±600 秒内 |

## 逃生阀

想临时回到「每天固定一个时间点」的老行为：

```bash
SCHED_FALLBACK=true bash /root/start.sh 4
```

效果：`plan_load` 只生成 `[今天/明天 UNATTEND_HOUR:00]` 单行计划，不抽签、不延迟。
描述会变成 `每天 01:00(固定单点,回退模式)`。

## 已知运维坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **flock 被继承** | 守护被 `kill -9` 后，遗留 `sleep` 子进程仍持锁 → 后续 `start.sh 4` 一直误判「已有实例在运行」 | `ls -l /proc/*/fd/* \| grep mrs_unattended` 找到持锁进程并 kill，再 `rm -f` 锁文件 |
| **crontab 重复膨胀** | 旧版用 `start_unattended.sh 4` 当标记，但实际写入的是 `bash /root/start.sh 4` → 永远匹配不上 → 每次启动追加一组 | v5 已修：统一 `CRON_TAG` 注释 + 实际命令串过滤（`_cron_strip_mrs()`），启动时幂等重写 |
| **不能用 `pkill -f "dist/index.js"`** | ssh 命令行本身也含该串，会把自己杀掉（exit 255） | 用 `pgrep -f "dist/index[.]js"` 再逐个 kill |
| **后台启守护的正确姿势** | 直接 `&` 会让 ssh 会话提前收到 SIGTERM（exit 255、无输出） | `ssh host 'nohup setsid bash /root/start.sh 4 </dev/null >/dev/null 2>&1 & disown; exit 0'` |
